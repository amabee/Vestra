# Seanime playback comparison

Compared the local Seanime source checkout at commit `4bdff7b2` with Vestra's native streaming path. This is source evidence, not a same-source playback speed benchmark, and does not establish that Go or C# determines buffering speed. Reference files were left unchanged.

## Findings

| Area              | Seanime source evidence                                                                                                                                                                                                            | Vestra implication                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser HLS       | `video-core/video-core-hls.ts` creates HLS.js with a worker, ordinary rather than low-latency mode, and 90 seconds of **back** buffer. Its quality helper returns `-1` for Auto; fixed quality sets `currentLevel`.                | Browser Auto delegates rendition selection to HLS.js. Its configuration is not an mpv tuning preset. Back buffer preserves already-played media; increasing it does not by itself accelerate future downloads.                                                                                                                                                                |
| Native playback   | `seanime-denshi/src/main/mpv-core.ts` initializes `@mpv-prism/electron`; the frontend consumes Prism's cache events.                                                                                                               | Native behavior also depends on the separately packaged Prism/libmpv implementation. The browser HLS settings do not establish its native transport settings. That package was not unpacked or reverse engineered in this comparison.                                                                                                                                         |
| Stall detection   | `video-core/video-core.tsx` uses a 12-second timeout and rejects stall recovery when playback advanced by at least 0.5 seconds, playback was paused, or readiness recovered.                                                       | Vestra previously relied on its cache-buffering flag. Added the playhead-progress check so a stale flag cannot unnecessarily reload or lower the quality of advancing video.                                                                                                                                                                                                  |
| Buffer visibility | `mpv-core/mpv-core-stats.tsx` reports cache duration and byte counts; `mpv-core.tsx` derives buffered progress from cache state.                                                                                                   | Added optional buffered seconds and download/read bytes per second from mpv's `demuxer-cache-duration` and `cache-speed`. The loader displays available measurements; unavailable values are omitted. This makes subsequent diagnosis measurable.                                                                                                                             |
| Provider results  | `internal/onlinestream/repository_actions.go` caches episode lists and source data and gathers advertised servers. `use-onlinestream-auto-provider-cycler.ts` supports bounded trials across servers/providers and source refresh. | Vestra shares in-flight extraction and short-lived source results and falls back across mirrors during extraction. Its playback recovery now tries untried mirrors within the selected provider before a lighter rendition; it does not reproduce Seanime's cross-provider trial workflow. Provider changes require preserving the correct title, episode and user selection. |
| HTTP proxy        | `internal/handlers/proxy.go` reuses HTTP clients/connections, forwards stream data, and supports a particular HTTP/2 negotiation fallback. `onlinestream-page.tsx` uses the proxy when provider headers are needed.                | Vestra passes provider headers directly to mpv. A proxy can solve transport/header compatibility, but another local hop is not evidence of a universal throughput improvement. TLS relaxation in some reference configurations is not needed for these changes.                                                                                                               |

## Changes implemented

- Native stall recovery requires an interval without meaningful playhead movement. Continued progress rearms the check; a later real stall can still recover.
- Native cache/read-rate observations are optional bridge fields and clear on media replacement. Invalid values remain unknown, rather than becoming fabricated measurements.
- Both loading surfaces show buffer health when available, with no raw stream URLs, tokens or credentials exposed. Rate updates do not generate repeated live announcements for screen readers.
- Retained Full HD preference, HD recovery, existing prefetching and startup improvements.

Checks cover advancing playback under a stale buffer flag, genuine later stalls, telemetry validation/reset and offscreen native-overlay display. Production build and TypeScript checks also apply.

## Remaining performance work

Measure the same title, episode, host and quality in both apps before claiming a speed multiplier. A browser HLS.js playback path with automatic rendition selection is a substantive engine addition, not a copied cache constant; codec, subtitles, provider-header transport and native-player fallback need to remain compatible. Native transport benchmarking and cross-provider trials remain separate follow-up work. Bounded same-provider mirror failover is now implemented; see [mirror failover](anime-mirror-failover.md). The diagnostics added here support identifying which of those will actually help.
